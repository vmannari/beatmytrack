# Achievements backend deployment, 2026-10-17

The owner explicitly requests backend deployment including Achievements. This release adds the approved permanent achievement service and its Challenge Club discovery prerequisite to the retained Studio/simulator backend. Schema advances from `0040_studio_platform` through `0041_challenge_discovery` to `0042_achievements`.

The release is built on the deployed image, using the reviewed feature patches in an isolated source snapshot. It includes the collection/featured endpoints, permanent race/creator milestones, competition and record processing, coalesced rarity projection and privacy erasure. The existing idle worker performs the additional bounded work; no new continuous service or scheduler is created. Existing challenges become private by default; public discovery requires deliberate public creation and the existing sharing policy.

The approved optional incident-summary plumbing is included so accepted clean races can earn their fixed bonus and clean achievements. Missing or malformed summaries do not grant clean awards or invalidate an otherwise valid trajectory. This remains lightweight client evidence rather than an independent collision simulation. Movement/gate checks, lap timing and the native canonical package retain the deployed compiler27 / physics0.59 / rules20 contract. Later concurrent game physics/rules and legacy-authoring retirement are excluded.

Achievement progress starts with this release. Existing historical runs are not converted into fabricated achievement unlocks, and viewing a collection does not award progress or enqueue work. The deployed handler performs two bounded achievement SELECTs. The new client catalog contains 40 families and 130 unlocks; showing the collection on a device still requires its matching game client. This task does not build or install an APK or perform physical-phone actions.

The rollout uses a fresh managed database backup, a short write-maintenance window, existing-data fingerprints, explicit migrations, a zero-traffic candidate, matching API/worker/job images and post-deployment checks. Existing Studio sample accounts, history, incidents, cases and money/Coin ledgers are retained. The financial source remains estimated simulation data; provider connections, real notifications and continuous watchdog hosting are unchanged.

Actual image/source hashes, tests, backup, serving revision, preservation results and browser checks are recorded in [the deployment evidence](evidence/achievements-backend-deploy-2026-10-17/). The initial isolated source merge encountered an older worker branch around the insertion point; the merge uses unique surrounding context from the reviewed feature patch and retains the first attempt. The existing native canonical replay/rewind fixture is checked during the image build. PostgreSQL tests cover the actual schema40-to42 migration and row preservation before the feature regression suite.

The previous image requires schema40 readiness. A rollback after migration must use a schema42-compatible package or a separately planned backup restoration with writers fenced; blindly routing the old image onto schema42 is not a valid rollback. No destructive downgrade or restore rehearsal is performed by this deployment.
