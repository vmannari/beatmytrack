# Egyptian Desert objects

Owner request, 2026-10-16: add ancient Egypt themed objects to Desert, with AAA as the visual quality target.

Requirements: EGY01, a coherent original Egyptian-inspired set; EGY02, Desert palette and native previews; EGY03, placement, scale, rotation, persistence and real solid footprints; EGY04, existing bounded caches, retained editor batches and rendering; EGY05, native visual evidence and explicit device acceptance. Existing camera, road, sand, audio, car condition, driving and scoring rules remain in force.

Create → Desert → Objects → Buildings now offers Pyramid, Obelisk, Lotus column (intact/broken variants), and Temple wall. Desert's existing Populate command includes the new monuments alongside rocks and existing props. Populate continues to produce saved editable objects with deterministic seeds, whole-footprint road clearance, start exclusion, minimum separation and the original 96-object limit. Existing saved and published tracks are not rewritten or automatically decorated.

The original native models use individually fitted limestone casing courses, narrow staggered joints and worn bevels; a tapered granite obelisk with closed corners and recessed carved registers; a fluted sandstone column with a shaped lotus capital, attached curved petal relief, neck binding, drum joints and a fractured shorter variant; and a battered block-built temple remnant with a closed curved cavetto cornice, broken crown and carved registers. The motifs are original inspired ornaments, not a claimed historical inscription or reproduction. Filtered mineral grain, restrained layering, rough surfaces and muted surviving pigments share one opaque stone shader. Original project shadows and contact projections ground the models. No external bitmap, model, service or runtime dependency was added.

Reference guidance only: [Egyptian Ministry, limestone pyramid casing](https://egymonuments.gov.eg/monuments/the-great-pyramid/), [Metropolitan Museum, palm column construction](https://www.metmuseum.org/art/collection/search/543936), and [Metropolitan Museum, composite papyrus capital](https://www.metmuseum.org/art/collection/search/551898). The shipping geometry and ornaments are original; no reference pixels or meshes were copied.

One extra opaque material batch assembles the Egyptian set in a race world. Editor groups retain a separate stone material key so ordinary opaque props keep their existing material. Cached authored normals survive assembly: masonry keeps flat faces and cut edges, while connected column profiles/petals use smooth normals. The existing 96-entry/32 MiB model and 48-image/24 MiB thumbnail limits remain. Thumbnails use the same models and release their one-shot viewports. Default geometry is below 7,000 triangles per object; the report records actual counts/hashes, including compatible concurrent hidden-face optimization. No new permanent viewport, process loop, texture sampler or light is added by a placed object.

Runtime files: `game/track/prop_egypt.gd`, `egypt_stone.gdshader` and their UIDs; Egyptian dispatch/normal preservation in `creator_prop_visual.gd`; stone assembly in `native_track_visual.gd`; `contact_shading.gd`; `game/editor/creator_catalog.gd`, `creator_objects.gd`, `object_population.gd` and `placed_object_batches.gd`. Validation: new `game/tests/test_egypt_props.gd` plus the expanded population expectations and covered-startup wait in `test_object_population.gd`. The wait accommodates the existing retained-Garage startup before editor navigation; no existing assertion was removed. The document schema keys and compiler/physics version remain unchanged; the catalog gains five accepted object IDs. Older clients cannot author/render these new IDs. There was no backend operation or rollout.

Actual commands use the pinned engine through `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev.ps1`. Test storage was isolated under `build/egypt-*-user` after the initial attempts. See [report.json](evidence/egypt-props-2026-10-16/report.json) for exact final results, retained logs, source hashes and the scoped patch.

Initial failures/corrections are retained in the report and logs. Sandboxed Godot initialization failed with Windows certificate-store/access errors; ordinary local execution passed. A first pyramid bevel exceeded its footprint by 24 mm and was brought inside it. The first temple cornice was insufficiently closed; it now has solid curved returns/caps. The obelisk shaft was rebuilt as connected recessed rings; collapsed cap triangles were removed. Curved petal relief was fitted to the actual capital profile; flute-following joints replace intersecting dotted rings. A low-sun triangular shading artifact persisted with shadows disabled: the cause was regenerated averaged normals across the tiny bevels. Preserving the authored normals resolves it without changing the game's lights or disabling shadows. A population fixture navigated before covered startup completed; its startup wait fixes the fixture. Two native attempts encountered a transient mesh-attribute upload error while a separate task was changing shared prop construction; subsequent complete native runs passed. Concurrent shared-geometry, editor-review and backend changes are preserved and excluded from the Egypt integration patch where separable.

No physical-phone test or attachment check, APK/export/install, production deployment, backend change, live track write, physics merge or full-project Validate was performed. Capture runs intentionally pause/reframe isolated fixtures and can print loading/capture hitch diagnostics; they are not frame-rate measurements. Owner acceptance remains for artistic quality, monument scale/occlusion and ornament readability; physical-device acceptance remains for touch use, dense-population memory/frame pacing and sustained motion. AAA is the requested quality target, not a certification made by these checks.
