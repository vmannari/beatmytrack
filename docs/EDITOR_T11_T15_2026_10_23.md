# Editor T11–T15: transaction ownership, safe preparation and current imports

Requirements: **T11, T12, T13, T14, T15, R01, Q01** from the [editor audit](TRACK_EDITOR_AUDIT_2026_10_23.md). The owner's current instruction removes the requirement to support older imported formats. This supersedes the audit's older-import conversion proposal.

T11's Winter material-group and duplicate-contact-shading correction was already implemented in [T05–T11](EDITOR_T05_T11_2026_10_23.md). This slice verifies that correction and implements T12–T15. Current modular road construction, published-track immutability, canonical compiler identities, physics and track dimensions retain their existing behavior.

## Implementation

**T12 — explicit transaction ownership.** `game/editor/editor_session.gd` owns undo/redo, gesture history reservations, the existing coalescing analysis queue, and validated/workflow snapshots. Each analysis request carries a monotonic revision. A receipt needs matching revision, library owner and source content before it can own live derived state. This also fences an older identical document after an A → B → A sequence. Earlier committed revisions still reach the ordered recovery writer; an uncommitted drag cannot suppress their durable save.

App remains the scene/UI and persistence adapter. Its small property forwards serve the current controls, telemetry and tests. This is a bounded extraction, not a new general editor framework. Operation-specific handles and selection remain in Canvas.

`game/editor/editor_gesture.gd` defines Idle, Pointer, Edit and Navigation phases and the document domains each tool can roll back. Navigation starts without copying the document; the first mutation captures only its tool's domains. Pinch rollback restores absent fields as well as values. Finishing navigation releases the transaction. Existing touch arbitration and the thin canvas drawing API remain intact.

`game/editor/road_piece_catalog.gd` supplies the seven piece titles, defaults and handle keys used by the palette, factory and canvas. Geometry sampling and validation remain explicit in `RoadPieces`, including versioned canonical geometry. Unsupported factory kinds return an empty result. Descriptor defaults preserve the established geometry hash.

**T13 — CPU preparation and main-thread publication.** The optional worker no longer constructs `NativeTrackVisual`, commits a mesh, reads a GPU mesh, creates a material, or mutates shared model caches. It owns a detached CPU helper and private SurfaceTools. Packed float32 positions support the existing hidden-face classification without mesh readback. Private tools retain authored smoothing groups and deferred assembly order; this avoids changing intermediate normal/colour encoding to flatten the preparation representation.

This follows [Godot’s guidance on avoiding GPU interactions from worker threads](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html).

Main-thread publication replays the existing mesh encoding, then applies Winter dressing and admits the final immutable mesh to the existing bounded cache. Assertions guard mesh publication/readback and cache mutation. The previous cache mutex and its long build-time critical section are removed because optional workers no longer access that cache. A shared model dispatch function serves cold construction and preparation.

Publication requires the latest selection generation and the same biome, and waits while a canvas pointer is active. Detaching the retained editor cancels and releases job ownership. Resuming the editor can start another job; a former coroutine cannot clear or publish over the new owner. The global work-job service still owns cancellation/reaping independently of the panel lifetime.

The burning-car sculpt reads a previously encoded wreck. Its optional worker warm-up is skipped; its actual model continues to build through normal main-thread installation. GPU publication still contains indivisible driver operations. It is **not** a hard frame-time guarantee, and no Android speedup is claimed.

**T14 — repair obsolete checks with current semantics.** The original road suite reproduced **377 checks / 24 failures**. Six hairpin cases each failed four old assumptions:

| Old assumption | Current check |
|---|---|
| Every road material has the original shader resource path | Read the semantic material retained by shader specialization; inspect asphalt/marking roles and masks. |
| Asphalt requires a separate flat edge-fringe draw | Require masked asphalt and an actual raised bevel. The existing raised road supplies the edge geometry. |
| Every non-kerb normal is straight up | Retain the strict upward-normal check for flat roles; require finite unit normals for shaped road/verge roles and a real asphalt bevel. |
| Rendered kerb height ends at 0.118 m | Compare every vertex against canonical kerb triangles plus the existing 0.018 m presentation offset and 0.05 m cosmetic asphalt lift. |

Kerb UV lengths, taper seams, bounded runs, crown/bevel normals, triangle population and unchanged canonical cells remain checked. The new vertex check also accounts for the renderer's +Y map to −Z world mapping. The suite passes **377 / 0** without changing road implementation or replacing its canonical geometry.

**T15 — current formats only.** Creator imports, draft reads, the compiler and catalogue accept **`creator-track-v5`**, with the five current biome IDs. The `coast` import/catalogue alias is removed from code and the v5 JSON schema. Native reads and trusted native construction accept **`surface-grid-v2`**; the v1 reader allowance is removed. Import/export size errors use the actual byte allowance rather than a stale 512 KB message. Schema values must be strings before comparison, so malformed numeric/array/object schema values fail cleanly.

There is no older-format reader, alias, automatic upgrade or conversion offer in these track-import paths. Rejected files remain untouched. Historical schemas, diagnostic corpus files and evidence are reference material, not runtime conversion support. Current v5 route/layout fields and native built-in bases remain part of the current authoring contract; they are not import migrations. Positive catalogue/result fixtures now use a current biome. Negative tests deliberately retain invalid old identifiers.

## Complexity policy

This change does not raise quotas. Concurrent capacity work now sets 1 MiB authoring JSON, 4,096 placed objects and 4,096 tyre stacks, with a 128 MiB live-prop estimate. Existing bounds retain 96 road pieces, 4,000 m cumulative section length and 96 route points, with the existing per-field dimensions/paint bounds. The newly introduced exemption for scenes within the former 96-object quota is removed: the current prop budget applies at every count. These are conservative authoring limits, **not** reference-device capacity certification.

Existing diagnostics expose rebuilt/reused sections, uploads, per-frame installed vertices and estimated active/transient/idle resource bytes. The shared retained-cache estimate and history caps from T05–T11 remain in force. Active worker tools, driver memory and transient allocations are not a hard-capped total. Use actual generated vertices, raster cells and retained-byte telemetry before changing limits; raw piece count alone is insufficient.

The updated earlier dense-track suite has **899 / 0**; its dynamic count changes because the 95-object fixture uses budget-admitted sheds rather than containers. No assertions were removed.

A later concurrent capacity integration made an old 94-null-object quota fixture invalid; it now supplies valid objects up to the current limit minus two. JSON syntax and declared schema/biome enums are checked; a general Python JSON-schema validator is not installed. Actual engine import/export and malformed-input paths are exercised directly.

## Remaining acceptance

Physical OnePlus Nord 2 5G profiling, sustained 20–30 minute memory/frame-time acceptance and owner touch feel remain unmeasured. Atomic GPU publication and cold shader/driver work can exceed 16.67 ms even on desktop; defer/measure them rather than describing this as certified 60 FPS editing. This slice does not resolve the earlier T08 driver limitation or certify all original audit performance targets.

A client reload and matching canonical validation sources are required for the new format policy. No phone attachment check or device test, APK, live account/backend mutation, publication, social send or deployment was performed. Other local work is preserved; the checkpoint excludes concurrent rotation, rendering, gameplay, audio and service changes.
