# Gameplay audit fixes F01, F02 and F03

23 October 2026. Implements the owner's request to fix the first three findings in [the gameplay audit](GAMEPLAY_AUDIT_2026_10_23.md). Source changes and desktop verification are complete. Android execution and sustained device performance remain unmeasured.

## Requirements and resulting behavior

| ID | Requirement | Implementation |
|---|---|---|
| GPA-F01 | Remove full records/settings commits from periodic cosmetic saving. | A profile-owned, versioned condition sidecar uses one low-priority writer, immutable packets and latest-revision coalescing. The five-second racing callback queues only cosmetics. |
| GPA-F01-R | Preserve local-only data, atomic recovery, per-car masks and commit-only PB/achievement semantics. | Legacy embedded conditions load unchanged. Sidecar primary/backup recovery, bounded validation, explicit lifecycle flushes and write-failure retry are independent of PB commits. |
| GPA-F02 | Avoid duplicate paint-exclusion rasterization and make cancellation effective inside it. | Compiler paint emits its exact exclusion footprint once; native-track preparation reuses it. Native/scalar paths coalesce identical work. Fallback rows and contact preparation observe cancellation; canceled partial tracks are discarded. |
| GPA-F03 | Remove avoidable distant/resting prop and tyre work without altering driving. | Retain descriptors, scratch arrays, buckets, pair order and geometry; use conservative swept candidates and proven stationary skips. Derived data stays outside canonical snapshots and rewind. |
| R01/Q01 | Preserve features, exact physics/track output and independent regressions; retain actual evidence. | Task-original reference files, exact state comparisons, unchanged compiler goldens, existing lifecycle/replay tests and paired measurements are retained. |

## F01: cosmetic persistence

`game/persistence/condition_store.gd` owns a small `<records-path>.conditions.json` file with schema 1. It validates the existing five-car cosmetic collection and caps file size at 128 KiB. There is one tree-owned service and writer per canonical profile path, with weak record-owner references. A packet cannot mutate while the writer serializes, verifies and atomically rotates its temporary/primary/backup files. Repeated updates coalesce to the latest revision. Failed writes retain the confirmed revision and retry with backoff.

`LocalRecords` mirrors live and confirmed cosmetic revisions without copying the full PB dictionary. `VehicleCondition` preserves its existing synchronous API for Garage actions and lifecycle saves; Game requests background operation only for its periodic callback. Existing finish, retry, pause/background and exit save sites retain their flush barriers. Last-owner removal and tree exit join the writer and flush the latest pending packet. Temporary files are never treated as committed data. No network or account data is involved.

Ordinary PB/settings writes retain their original validation, atomic commit, rollback and achievement notification behavior. They can still include legacy cosmetics, after flushing the sidecar. Full-store result/settings writes remain synchronous; this fix specifically removes the recurring cosmetic trigger during driving. A lifecycle flush may wait for the small outstanding write. Storage failure is reported and cannot commit a PB or achievement accidentally. There is no guarantee of retaining the last queued cosmetic revision after forced process termination.

Changed runtime files: `game/core/game.gd`, `game/persistence/local_records.gd`, new `game/persistence/condition_store.gd`, and `game/vehicle/vehicle_condition.gd`. The hitch-monitor test now injects its original 180 ms delay at the new condition-save boundary, retains every timing assertion, and uses a disposable records path.

## F02: one paint footprint and cooperative cancellation

`TrackCompiler._paint()` accumulates the union of unprotected paint coverage alongside the existing ordered cell/road-mask writes. That footprint is passed through `NativeTrack.from_data()` into `RoadKerbs.build()`. Final solid cells are still included. Preview reuse stores the footprint with its raster key and counts it against the existing 8 MiB auxiliary allowance; prepared-track snapshots remain under their existing separate budget.

The optional native result adds an exclusion buffer without changing the method or required feature version. An older library continues painting and falls back to the cancellable scalar exclusion builder. The native and scalar algorithms retain oriented endpoint calculations, paint order, road protection and surface assignments. Identical oriented capsules within a stroke and consecutive identical strokes are idempotent. The exclusion-only fallback also deduplicates identical coverage across strokes and skips cells already covered.

Cancellation is checked inside raster rows, segment/contour preparation and Winter contact preparation. `from_data()` returns null after cancellation, preventing partially prepared contact data from reaching a race. This removes the audited uncancellable duplicate raster loop. Arbitrarily complex unique strokes still consume work proportional to their coverage; no claim is made that every legal track now loads within one fixed latency budget. No authored content is rejected or simplified, and the compiler remains version 27 because exact output and identities remain unchanged.

Changed files: `game/editor/track_compiler.gd`, `game/editor/prepared_track_cache.gd`, `game/track/native_track.gd`, `game/track/road_kerbs.gd`, `game/track/snow_banks.gd`, `native/track_geometry/raster_geometry.hpp`, `native/track_geometry/track_geometry.cpp`, the extension descriptor and its matching Windows/Android binaries. Native provenance is updated separately.

## F03: retained deterministic prop work

`LightProps.step()` retains filtered immutable descriptors/radii, detects in-place descriptor changes, and prepares breakable data only when relevant. A conservative swept rectangle excludes distant simple props before the original exact car test. Proven zero-motion world queries are skipped; signed-zero edge behavior is preserved. Burning barrels, breakable contacts and fragments retain their specialized simulation.

`LooseTyres.step()` retains scratch buffers, spatial buckets, stable ordered pairs and pair geometry while canonical positions remain unchanged. Every canonical row is still inspected, so rewind/restoration and in-place mutations invalidate derived geometry. Swept car candidates are collected in ascending body order; large query spans conservatively use all bodies. Original friction, impulses, contact thresholds, 16 solver iterations and four separation passes remain intact. Metadata caches are excluded from snapshots, rewind properties and uploaded race data.

Resting-row checks remain O(N), and retained buffers trade bounded per-state memory for less repeated allocation. Dense interacting tyre piles still have the separate F04 pair/solver scalability limitation. Active islands, altered sleeping thresholds or reduced iterations were deliberately unnecessary for this fix. Handling parameters, physics version 0.66, 120 Hz stepping and competitive timing are unchanged.
