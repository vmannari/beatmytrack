# Gameplay audit F04 and F05 implementation

23 October 2026. Requirements: GPA-F04 (dense tyre contacts), GPA-F05 (cooperative race installation), R01 (regression evidence), G01 (preserved presentation), Q01 (reviewable checkpoint). F01–F03 and concurrent editor/backend/presentation work are retained.

F04 now has an optional compiled, ordered dense-tyre solver. F05 uses cooperative world construction in the actual App race path, with an explicit readiness barrier and owned cancellation. Physics 0.66, compiler 27, visual kit 212, handling constants, five-lap rules, camera, materials, particles and artwork remain unchanged.

Evidence, raw samples, initial failures, source fingerprints and the task-only patch are in [evidence/gameplay-f04-f05-2026-10-23](evidence/gameplay-f04-f05-2026-10-23/). This is a shared dirty workspace, not a clean repository-wide release checkpoint. `effective-before/` removes only this task's changes from shared files; it preserves the concurrent editor changes present in the final files. No unrelated changes were reset or committed.

## F04: ordered dense contacts

- [tyre_contacts.gd](../game/vehicle/tyre_contacts.gd) selects the optional native path at 48 bodies. Smaller fields and absent/older/unsupported extensions use the existing GDScript solver. Supported canonical tracks expand to at most 576 tyre bodies; the native packet rejects more than 4096 before mutation.
- [tyre_contacts.hpp](../native/track_geometry/tyre_contacts.hpp) retains spatial buckets, ordered pair geometry, candidate indices and compact velocity/correction buffers on the canonical state's owner. Rewind, external coordinate/count changes and restored snapshots invalidate the positional cache. Metadata is excluded from canonical snapshots and rewind and released with the state.
- Pair order, sixteen velocity iterations, four separation passes, friction, contact response, collision counting, spin and scalar/vector rounding boundaries retain the original algorithm. This is an exact port, without changed handling or approximate contact islands. Floating-point contraction and fast-math are disabled.
- A certificate restricted to the exact base `NativeTrack._contact` allows a cheap zero result only when its entire query rectangle is in bounds and contains no solid cells. Each step reads the current packed grid. Bound/custom callbacks, subclasses, solid cells and map boundaries retain the original callback. Custom callbacks retain eager row updates; certified grid-only queries permit compact ordered corrections before publishing the same canonical values.

Seven alternating fresh-state pairs per scenario were measured on Windows, i7-11700K, pinned Godot 4.7.2, using the independently frozen post-F03/pre-F04 script. Values are median **microbenchmark stage times**, not full physics ticks or Android timings.

[dense-profile.json](evidence/gameplay-f04-f05-2026-10-23/dense-profile.json) retains all samples, capacities and query counts. Dense pair storage remains quadratic: the 576-coincident grid case reserves about 7.36 MB of native vectors, excluding map buckets/allocator overhead. This change substantially reduces the measured bottleneck; it does **not** establish a worst-case 120 Hz guarantee for every legal overlapping layout. Device profiling must precede any further island/sleeping/contact changes. Such changes need independent exact validation or an explicitly approved/versioned gameplay change.

## F05: installation and lifecycle

[App._start_race](../game/core/app.gd) sets cooperative preparation before attaching a disabled Game. It polls `preparation_complete`, rechecking loading ownership, account scope, navigation, car and track selection. Construction completion is followed by the existing covered material/effect/bridge/Night draws; only then does App enable gameplay and release the loading cover. The ordinary countdown still starts at 360 ticks, and timed state/recording remain at tick zero throughout installation.

[Game](../game/core/game.gd) owns partial visuals before its first await. Ground/bridge sampling uses the existing low-priority, cancellable, joined WorkJob lifetime. Scene/resource creation stays on the main thread. World building uses the existing cooperative upload path, with checks between weather, car, weathering, effects/audio and HUD phases. Snow-bank height preparation yields internally without changing its exact sparse world-space heights. Physics, presentation, key input, pause/focus behavior and premature result/retry/draft callbacks are fenced until ready.

Focus lost during incomplete loading is retained. If loading completes in the background, the race starts paused with the full countdown; returning before completion clears that pending state. This pause avoids capturing the loading cover as a frozen race image. Ordinary active-race pause behavior is retained.

[PreparedWorldCache](../game/track/prepared_world_cache.gd) retains its synchronous API and 64 MiB/five-entry allowance. Cooperative pack/restore yields between resource inspections, child duplication and transfer. A tree-owned [staging lease](../game/race/install_staging.gd) frees unattached temporary holders if the owner disappears during an await. Only complete, current snapshots enter the cache. Cancellation, timeout, navigation and teardown discard incomplete worlds and restore the menu.

[SpatialMeshChunks](../game/track/spatial_mesh_chunks.gd) retains its synchronous API and the original ordered geometry. Cooperative splitting checks between triangle groups, index remapping, attribute copying and uploads. Race source families remain tree-owned across waits. Independent fixtures compare exact arrays, transforms, metadata and output order.

The existing sliced Desert deformation path split one source surface into many upload surfaces. Simply enabling it for racing would increase steady-state draw calls. Race installation now retains the original complete surface/index streams while moving deformation to the worker; editor uploads retain their previous split behavior. This preserves actual race geometry and draw count. Large original surfaces remain indivisible engine uploads and can exceed the ordinary vertex budget; this is deliberate and is reported, not a claim of a hard per-frame upload cap.

Tiny non-refining Desert prop meshes (at most 384 source vertices) use the same deformation calculation directly and share the race's time-budget checks. This avoids a worker and unconditional frame waits for every small mesh. Large/refining surfaces retain the worker; the editor path retains its existing scheduling. Whole-world equality checks fence both paths.

Standalone desktop Mobile renderer (RTX 3090), three alternating pairs per biome. Median milliseconds:

| Environment | Synchronous blocking attach | Cooperative initial attach | Cooperative P95 observed gap | Cooperative largest gap | Total sync / cooperative |
|---|---:|---:|---:|---:|---:|
| pine | 1674.162 | 1.261 | 15.852 | 88.351 | 1674.164 / 1946.519 |
| winter | 453.012 | 1.172 | 27.471 | 111.473 | 453.013 / 698.734 |
| desert | 1069.613 | 1.198 | 17.226 | 63.661 | 1069.614 / 2038.016 |

[loading-profile.json](evidence/gameplay-f04-f05-2026-10-23/loading-profile.json) contains every observed interval, installation counters and optional phase timings. A reported largest gap is the median of the three per-run maxima, not a pooled percentile. The Desert fixture retains one 42,040-vertex indivisible original surface, exceeding the ordinary 24,576-vertex install allowance. Total loading time increases while frames remain serviceable; this change targets responsiveness and safe activation rather than shorter total waits.


The paired probe prepares the same CPU road/Winter packet outside the timed region, warms shared resource/code caches equally, clears race-world and road-GPU caches for each sample, and alternates synchronous/cooperative construction three times per environment. It measures standalone disabled-Game installation, excluding network, track compilation, disk artifact creation, App authorization and subsequent covered shader warmups. Frame gaps include engine scheduling and rendering; they are not isolated CPU or GPU times. Total preparation can increase because UI/render frames and worker waits are now serviced. No 60 FPS loading guarantee is claimed.

Some resource operations remain indivisible: engine mesh/texture creation, cache scene packing and effects/audio construction. Cooperative yielding removes the long synchronous construction block but cannot guarantee 4/6 ms for every such call. The large Desert surface exception preserves the original rendering cost. These remaining units need device traces before further changes.

### Corrections and unresolved diagnostic limits

The first native build exposed a C++ declaration ambiguity, corrected before validation. Early fixture use of a dynamically loaded VehicleCatalog configuration retained resources; the focused solver fixture now loads the balanced resource directly. A trial `@static_unload` annotation caused shutdown trouble and was removed; the final adapter has no static variables. The existing heavy tyre test now starts deferred, with its exact assertions unchanged; intermittent earlier post-comparison shutdown failures were investigated with a previous-library control and a native debugger, but their root cause was not conclusively isolated. Later normal runs and the old-library fallback exit cleanly.

The first integration test caught a stale editor barrier builder after owner teardown; its entry now checks current ownership. The cache test caught the need for an owned holder during awaited packing/restoring. A Winter cached-material assertion initially required shared object identity for a material deliberately duplicated per race; it now compares executable shader code and every uniform, retaining all geometry/placement checks. The new mesh test initially gave the nonadaptive control different parent/name conditions; these now match. The parser caught a coroutine API compatibility issue; the original synchronous `SpatialMeshChunks.add` interface is preserved through a callback-free shared implementation.

The full-world comparison rejected the first sliced Desert version because it produced additional mesh surfaces. The final race path preserves exact original surfaces rather than weakening that comparison. Earlier loading probes also omitted the App's prepared Winter cover; the final probe includes that cover. Retained intermediate samples/logs remain identified separately. The runner uses PID-based log directories, which can be reused; the correction narrative also records early attempts whose original logs were overwritten by a later process with the same PID.

Final lifecycle inspection also identified that simply ignoring a focus-loss notification during asynchronous startup could activate a race in the background. The final code retains that notification and tests both background completion and return before completion. Paired performance samples precede this last focus guard; the normal foreground construction and physics paths measured there are unchanged.

The first pause-fixture command was mistakenly headless despite waiting for render signals. Only that owned test process was stopped. The required graphical rerun passes all 17 original assertions; an optional evidence-directory argument keeps its captures in this task's directory. The runner rejected a temporary outside-tests script path before execution; the original test remains the exercised fixture.

OpenGL profiling-harness runs reported one 87,380-byte texture at renderer shutdown, including a Winter-only probe. Clearing caches, an extra draw and deferred shutdown did not establish a fix. Those runs are retained as diagnostic measurements and are **not** counted as clean profiling passes. The desktop Mobile full profiling run and actual loading/graphics/ghost regressions are recorded separately. The GL shutdown issue has not been attributed conclusively to production code or the harness and remains an explicit follow-up.
