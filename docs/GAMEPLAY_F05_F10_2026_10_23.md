# Gameplay audit fixes F05–F10 — 23 October 2026

The owner authorized implementation of audit findings GPA-F05 through GPA-F10. F05 was already implemented with F04; this task retains that loading pipeline, extends it to the newly partitioned prop families, and revalidates the actual App path. The remaining findings are implemented locally. There is no vehicle-handling, checkpoint, lap-time, input-packing, canonical rules or backend change in this task.

Evidence, actual command receipts, initial corrections, source hashes and the task-only checkpoint are in [the evidence report](evidence/gameplay-f05-f10-2026-10-23/report.json). Measurements use pinned Godot `4.7.2.stable.official.ed1daf0bf` on Windows; graphical tests use an RTX 3090 with Compatibility and desktop Mobile renderers. These are standalone script tests, not exported release Android measurements or a sustained 60 FPS certification.

### Geometry and loading

Spatial grouping uses ordered draw-corner ranges, adjusted for enclosed faces removed at commit. It does not infer object membership from the indexed vertex numbers. Keeping a whole prop in one draw avoids changing the ordering of its overlapping roof/trim faces. Ordinary small aggregates retain the original early-out; editor detail behavior stays in its existing path. No mesh simplification or collision change is involved.

Re-uploading decoded normals can truncate their octahedral encoding by one code. The partitioner preserves the original packed normal/tangent bytes instead. It uses the pinned engine's serialized ArrayMesh surface packet because the headless dummy renderer ignores vertex-region updates. This internal storage contract needs the exact geometry tests whenever Godot is upgraded. Runtime splitting yields within grouping, remapping, attribute copying and packed-stream copying; the complete original is freed after successful nonduplicating partitioning. Cancellation releases the staged original.

Cooperative loading still has indivisible engine operations. This task does not establish a hard maximum loading-frame duration. The previous F05 loading measurements and remaining cold driver/upload limits remain in [the F04/F05 report](GAMEPLAY_F04_F05_2026_10_23.md).

### Night lighting and appearance

Scenes with eight or fewer eligible world lights retain all of them. Crowded scenes deliberately change which lamps illuminate the surroundings: a stable nearby pool replaces unsupported, order-dependent overlap. Godot documents the [per-mesh omni-light limits](https://docs.godotengine.org/en/4.7/classes/class_omnilight3d.html). Distant lamp models and emissive faces remain visible. Vehicle spotlights are separate. The selector keeps scratch scores/order between updates and performs no simulation or network work.

Barrel fuel/motion updates publish availability through the same selector, so they cannot re-enable a ninth light. Extinguished lights release their slots. Restart primes selection after placing the actual camera. Prepared-world copies recover authored visibility, and covered shader warmup restores the exact selected set. This task does not claim invisible transitions in arbitrary overlapping user layouts; owner acceptance of crowded Night lighting remains necessary.

### Textures and rewind

Compressed artwork includes Desert apron/road/sand, dust, meadow/painted grass, Night ground/asphalt wear, Winter ice and snow. PNG masters are unchanged. Dune slope factors, grass normals/macro masks, surface factors, glass data, frost, Winter finish/seam and wind-flow imports remain byte-exact. High-quality-only ASTC/BPTC imports were rejected for this slice in favour of the broader S3TC/ETC2 variants described by the [image import documentation](https://docs.godotengine.org/en/latest/tutorials/assets_pipeline/importing_images.html). Compression is lossy artwork storage; it is not applied to canonical surfaces or numeric masks.

Rewind keeps scalar pose fields directly readable by ghost markers. The packed body codec preserves exact Variant types and numeric precision. Telemetry journals retain immutable dictionary references and per-snapshot prefix counts; lap resets, decimation and resumed branches get independent journals. Restore materializes lists only when selected. The ten-second/101-entry window, checkpoint cadence, launch penalties, credit rules, glass state and replay behavior remain unchanged. Explicit field coverage tests guard future schema additions. Full snapshots and journals release with their race history.

## Measured results

| Probe | Before | After | Interpretation |
|---|---:|---:|---|
| Ten artwork textures, complete mip payloads | 46,132,799 bytes | 8,397,544 bytes | 81.8% smaller decoded GPU-format payload for both S3TC and ETC2 artifacts; not total app RSS/PSS or measured VRAM residency. |
| Rewind tracked allocation, 101 checkpoints | 16,403,176 bytes | 4,007,764 bytes | 75.6% lower in seven alternating desktop pairs; includes newly appended telemetry samples. |
| Rewind median capture | 0.253 ms | 0.098 ms | Median of seven per-run medians, 576 tyres and 400 initial plus 202 appended telemetry samples. |
| Rewind per-run P95 capture | 0.341 ms | 0.128 ms | Median of seven P95 values; excludes the rest of the physics tick. |
| Local Winter prop view, submitted primitives | 95,436 | 23,886 | Twelve spaced castles; ~75% fewer primitives including unchanged auxiliary geometry. |
| Local Egyptian prop view, submitted primitives | 50,220 | 12,582 | Same camera/layout methodology. |
| Local warehouse view, submitted primitives | 117,516 | 29,406 | Same methodology; no changed pixels in the final native comparison. |

All three final prop before/after images are byte-identical in both native renderers. Spatial splitting trades some draw calls for fewer submitted triangles: Mobile draws increased from four to six; Compatibility from five to ten in these isolated views. Wider views can have more draw submissions without a geometry reduction. GPU timings are retained as observations, not universal speedups: the final Mobile prop stage medians were 0.193/0.126 ms, 0.102/0.083 ms and 0.147/0.119 ms before/after. Full-track/device acceptance must assess that trade.

The fire fixture has 32 volumes, fixed noise/time, opaque depth occlusion and two overhead scales. The 12,000-sample independent density-bound test skips 7,207 provably empty samples with zero false-empty cases. Native fire comparisons differ by at most one 8-bit colour code. GPU timing varies between runs and views; far-view savings are clearer than near-view savings. See both renderer JSON receipts rather than treating desktop sub-millisecond stages as an Android frame budget.

All five biome images pass the preselected mean colour error ceiling of 2.04/255 (0.8%) for desktop compression and decoded ETC2, on both renderers. Actual mean errors are below 0.81/255 for desktop and 0.63/255 for ETC2. Local maxima are retained in the reports; the result is not pixel identity. A separate dust alpha comparison passes. ETC2 packets are validated headlessly and decoded with complete mips for desktop comparison: this RTX driver lacks ETC2 support and its Vulkan upload fallback errors. No Android execution is implied by those decoded-image tests.
