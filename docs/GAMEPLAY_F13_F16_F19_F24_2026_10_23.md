# Gameplay F13, F16, F19 and F24

23 October 2026. Implemented locally on the current working tree, preserving concurrent work. Pinned Godot **4.7.2.stable.official.ed1daf0bf**, Windows / RTX 3090. These are standalone engine tests, not exported Android release measurements.

## F13: exact handling and ordered candidates

The concurrent creator-capacity work already supplied type-specific spatial indices and sorted source indices. This change builds on that implementation. It does not replace the physics formulas or claim those earlier changes as part of this task.

`NativeTrack.begin_creator_queries()` validates the public source values once for an atomic simulation or presentation scope. Nested queries reuse that validation; exiting the scope restores ordinary value checking. `VehicleSimulation.step()` wraps the original body, so rolling, airborne and other early returns cannot leave a scope open. Public in-place edits remain observable between scopes and by direct queries. Ground preparation builds the CPU index behind the existing readiness barrier.

The original narrow phases, trigonometry, swept contact sampling, arithmetic order, first matching ramp and source order remain authoritative. In particular, `step_speed_bumps()` retains **both** ordered nearby candidates and the independent **global nonempty bump-list flag**. A distant bump still causes the original load-transfer spring evolution even when the nearby list is empty. A truly empty original list retains its original early return. No handling, collision, timing, physics-version or rules-version change is intended.

Validation includes byte-exact full `VehicleState.snapshot()` comparisons on every tick of 240-tick drives for all five cars against the original simulation with full-list hazard methods; 600 point/sweep cases; overlapping ramps; rotations/scales; distant versus absent bumps; airborne/elevated/rolling spring cases; mutation invalidation and early-return scope cleanup. Existing 9,046 speed-bump and 212 hazard checks pass.

The query benchmark uses a deliberately synthetic **4,098-entry direct hazard list**, including two overlapping ramps. It bypasses authoring admission and does not certify a legal 4,098-object track. Five batches of 120 synthetic ticks perform eight ramp queries per tick. Final headless medians are **7.868 ms before / 1.017 ms after**, against the captured pre-task value-check implementation. This isolates repeated source validation and queries, not the whole vehicle, render frame or Android workload. One full source validation remains O(N) per scope to preserve public mutation semantics; there is no claim that dense-track CPU cost is constant.

Files: `game/track/native_track.gd`, `game/vehicle/creator_queries.gd`, `game/vehicle/vehicle_simulation.gd`, `game/core/game.gd`, `game/race/race_ground_preparation.gd`.

## F16: one bounded evidence lifetime

`race/attempt_evidence.gd` owns the monotonic input limit, shared with the completed-result queue and ghost tick limit. It accepts exactly **216,000 input frames** (30 active minutes at 120 Hz, including inputs later rewound). The following input marks overflow without appending a partial continuation. Local driving, physics and scored timing continue. Overflow invalidates online evidence and ghost output and produces an explicit local-driving message. Restart creates fresh evidence ownership.

Movement proof has an additional hard **36,032-sample** bound, including allowance for initial/lap/rewind boundary samples. Overflow is sticky across branching and exports no proof. Ghost overflow is also sticky. Incident journals retain at most **8,192 events per lap**. Truncation travels through completed laps and exact rewind snapshots; missing incidents cannot establish a clean-race achievement or clean-race bonus.

The result path checks eligibility before announcing online verification, challenge/Rivalry pending state or queuing an upload. It preserves ordinary local PB saving. Cloud-track results explain the recording limit without falsely claiming a failed local save succeeded. Draft validation becomes ineligible after overflow. Resume confirmation rejects unusable evidence **before** consuming a credit, including the exactly-full input list where no future input could be recorded. Input offsets remain monotonic through three rewinds even though scored ticks move backward.

Normal five-lap races retain the existing recording schema, sampling cadence, handling and timing. No backend protocol or server limit changes are required. The limit tests exercise budget edges, forced proof overflow, sticky branching, actual resume/upload entry points, bounded incidents and rewind restoration. The final integration test also crosses the cap through the actual physics callback and restarts the game.

Files: `game/race/attempt_evidence.gd`, `game/backend/race_proof.gd`, `game/backend/result_save_queue.gd`, `game/race/personal_ghost_run.gd`, `game/race/lap_telemetry.gd`, `game/race/rewind_history.gd`, `game/race/race_incidents.gd`, `game/core/game.gd`, `game/core/app.gd`.

## F19: compact release diagnostics

Release builds default to a **64 x 8 signed 64-bit packed ring** (4 KiB payload), retaining wall/frame time, tick, countdown, callbacks, draw boundary, blocked state and input count. Ordinary compact frames allocate no row dictionaries and do not enable Game's detailed timers, traverse emitters/render items, query engine performance monitors or sample camera frusta.

Dictionaries are materialized for hitches and their 16-frame after-windows, or an explicit inspector read of `latest`. The existing eight-worst-event policy, foreground/pause exclusions, asynchronous local writer, file limits and teardown ownership remain. Debug builds retain full diagnostics by default. `-- --race-hitch-detail` opts a release run into full diagnostics; the Game property also permits an explicit test/development selection.

The final headless fixture measures **1.759 us compact / 42.205 us full** per observer call over 1,000 calls. This is the observer body on this fixture, excluding nested Game timers, pre-draw sampling, OS storage tails and actual GPU time. It should not be substituted for the audit's different 124–142 us full-world measurement. Native full diagnostic callback tests still pass 47 checks, including deliberately delayed callbacks and persistence.

Files: `game/diagnostics/race_hitch_monitor.gd`, `game/core/game.gd`.

## F24: worker-owned numeric road cache

Production App loading and editor Save use the existing numeric `.arrays` representation. CPU workers perform geometry preparation or cache verification/decompression and optional compressed serialization/checksum generation. No worker reads back GPU mesh arrays or calls `ResourceSaver` on live rendering resources. The main thread publishes a small scoped receipt and installs mesh resources/nodes behind the readiness cover. In-memory road-node restoration now yields after a roughly 4 ms installation slice and honors cancellation; existing prepared-array upload budgets remain.

The existing private directory, engine/track/kit/theme identities, checksum verification, object-disabled decoding, size/count/residency bounds, atomic publication and eviction remain. Old `.res` presentation caches are disposable: the production path rebuilds them once into numeric arrays rather than synchronously decoding opaque resources. Player documents, PBs and other saved data are untouched. Synchronous resource helpers remain for explicitly noncooperative offline tools and legacy final-geometry cache tests; production App callers pass their tree owner and use the worker path.

Optional editor cache writes have one active worker and one coalesced pending track. Abandoned race-preparation jobs retain owned cleanup until their worker finishes. Shutdown joins preserve return packets so receipt owners can discard private pending files. No live-race callback joins a worker. Selected-track preparation no longer treats legacy resource-file presence as grounds to skip the CPU preparation path.

All five biomes round-trip exact numeric arrays and retain exact worker geometry. Corruption fails closed, pre-cancelled writes create no receipt, abandoned jobs release packets/receipts, and optional Save rebuilds without GPU readback. Complete synchronous/cooperative world geometry, materials, masks, placement and rendering flags have identical signatures in headless, native Compatibility and desktop Mobile. The real loading suite passes 1,343 checks, including cached restarts, focus, cancellation, navigation and countdown/input gates.

This improves main-thread scheduling; it does not establish total load-time or Android P95/P99 improvement. A single mesh upload, texture creation, small receipt commit/eviction or driver call is still indivisible. Cold migration can take longer overall because it prepares and serializes a numeric artifact.

Files: `game/track/native_track_visual.gd`, `game/track/road_cache_bakes.gd`, `game/editor/road_preparation.gd`, `game/editor/work_job.gd`, `game/race/selected_track_preparation.gd`, `game/core/app.gd`.
