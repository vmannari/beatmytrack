# Garage appearance sync — 2026-10-23

ALS01–ALS05/R01/Q01 implement the owner's report that car liveries and related customizations do not follow the account between devices. The previous Garage saved only local settings; Rivalry uploaded a selected-car snapshot but never restored the player's cars. The shop also retained its initial records object when the App selected an account profile.

All five cars now sync their body/accent/detail pigments, livery pattern, hood/roof sticker transforms and supported cosmetic parts. Sign-in restores saved designs, successful local commits schedule a 750 ms coalesced sync, and a 30 second timer checks for changes/retries. Rivalry delegates to the same adapter. The retained Garage updates its current model, thumbnails and controls without interrupting an uncommitted paint/sticker gesture. Ownership reads and purchase recovery now bind to the selected account's records.

ALS01: private authenticated `GET /v1/me/appearances` reads the existing bounded `Player.vehicle_appearances` map. `PUT` accepts one `appearance` and its `previous` acknowledged value (or null). Existing strict appearance validation restricts the five vehicles, known patterns/stickers, colors, transforms and Compact-only parts. No database migration is needed. Both the new endpoint and legacy Rivalry writes serialize on the owner row. A stale same-car write returns 409; repeating an already committed value succeeds without changing another car. The new wire schema is in `backend/schemas/vehicle-appearance-sync-v1.schema.json`.

ALS02: acknowledged values and attempted uploads live in the same atomic local save as the car edits. Lost replies, a second edit while a request is pending, a restart and acknowledgement-storage failure retain recovery information. JSON versions are normalized back to integers before sending strict API requests. Clean cars never upload defaults, and an unchanged refresh does not rewrite the profile.

ALS03: separate cars merge independently. On first adoption, an existing server car takes precedence over an unversioned local car; locally authored cars missing online are uploaded. If two devices edit the same car from the same acknowledged value, the first accepted online edit wins and the other device restores it. An acknowledged pending upload is distinguished from an unrelated remote edit so a newer local change after a lost reply survives. Older client releases can still use their legacy unconditional Rivalry writer; matching client updates are needed for the complete concurrency policy.

ALS04/R01: account/origin and records-generation checks fence every HTTP completion. Real App sign-in binds both sync and shop to the account profile; sign-out restores Guest and exposes no account paint. Existing server account erasure clears the same appearance map. Purchased unlocks continue through the existing authoritative economy API; appearance sync does not mint ownership or money. Dirt/washing condition, personal bests, device settings and canonical race contracts retain their existing local/separate behavior.
