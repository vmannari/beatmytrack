## Findings

**[P2] Rejected preview generations can overwrite the published PNGs.**

In `scripts/bake_garage_previews.gd:69`, each picture is written directly to its final filename. Source and previous-provenance checks run only afterward, at lines 75–84. A source/provenance rejection therefore leaves the new images with the previous manifest. `GaragePreviewCache.catalogue_texture()` loads those filenames directly, without checking that manifest. This can show an unaccepted generation after a failed or concurrent bake.

An isolated failure-injection run confirms this: the actual producer was copied to the disposable review directory, its output directory redirected to a private copy of the catalogue, candidate paint changed in that copy, and the existing post-render source-rejection branch forced to reject. It returned failure, **all six private PNG hashes changed**, and **the provenance file remained byte-exact**. Production images were not touched. A first control with unchanged candidate pixels also rejected, with identical output bytes; the changed-candidate test establishes the destructive case.

Render into a private generation, validate its sources/revisions and concurrent manifest state, then publish a consistent image/manifest set while preserving the last accepted generation on rejection. This is a publication fix, not a reason to simplify the visible models further.

**[P2] The workshop equivalence gate mistakes generated node numbers for geometry changes.**

`game/tests/test_menu_responsiveness.gd:15` serialises every Node3D name and transform, then line 44 requires complete array equality. Current source construction and the baked room contain **518 comparison rows**; **132 differ, all solely in autogenerated names** such as `@MeshInstance3D@2144` versus `@MeshInstance3D@2582`. All other compared fields—including transforms, mesh arrays, layers/shadows and finish properties—match exactly. The existing suite consequently reports **35 checks / one failure** even though this diagnosis finds no master-geometry difference.

Give generated nodes stable names, or canonicalise only the engine-generated identifiers in this test. Keep authored names and the mesh/transform/finish assertions intact. Rebuilding merely to align a global node counter is not a reliable repair.

**[P2] Workshop provenance is not covered by the export preflight.**

The recorded `vehicle/car_mesh_lods.gd` source hash in `game/assets/garage/workshop_v1.provenance.json:29` is stale. The scene still matches its recorded scene hash and the previous pass's resource bytes. However, the explicit export checks in `scripts/dev.ps1:377–380` inspect prepared cars and catalogue pictures; `check_prepared_assets.gd` traverses cars, modules and the header, not the workshop. Searching the production/preparation scripts finds the workshop provenance filename only in its writer. `GarageEnvironment.build()` loads the scene without validating that receipt.

Add a read-only scene/source provenance check to the export gates. The workshop baker should also snapshot inputs before construction and verify them before publication: it currently writes the live scene at line 25 and hashes sources only afterward at line 29. These are related gaps in the publication path. No export was attempted to test them.
