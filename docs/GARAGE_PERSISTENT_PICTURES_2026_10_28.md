# Persistent Garage preview pictures (2026-10-28)

The carousel already rendered photographs, but its saved PNG keys included the entire client build. Unrelated interface changes discarded otherwise reusable pictures. A cache miss at the front of the queue could also prevent later stored pictures from loading. Clean saved snapshots missed the bundled clean photographs, and photographs transferred from the preloader were never written to disk.

| Requirement | Result |
| --- | --- |
| GPP01 | Keep custom preview PNGs across launches and unrelated menu/translation/backend changes. A generated fingerprint covers the conservative native model/room/livery/handling/engine dependencies, including prepared assets. Appearance and relevant source changes still invalidate pictures. |
| GPP02 | Read every visible stored picture before constructing a missing preview. File loading continues while the existing input/idle gate prohibits GPU work. |
| GPP03 | Recognize an exactly clean version-1 saved condition as the original clean finish, allowing the bundled factory picture. Dirty, wet, fitted and repainted cars still require their own exact picture. |
| GPP04 | Persist the exact preloaded picture asynchronously, then recover it without another capture world. Keep the original one IO worker, one renderer, atomic PNG write, decoder validation and 14-file bound. |
| GPP05 | Keep both native capture paths at the PNG reader's fixed 2048 × 512 resolution at every display scale. Restore the main live showroom's original display-dependent resolution after the preloaded capture. |

Runtime changes are confined to `game/ui/garage_preview_cache.gd`, `game/ui/garage_preview_renderer.gd`, `game/ui/garage_preloaded_studio.gd` and the preview fingerprint generated by `scripts/build_identity.ps1` in `game/core/build_identity.gd`. The existing full build ID continues to track all shipping source changes. Hashing reuses the build step's existing per-file digests; no runtime source scan is added. `scripts/test_build_identity.ps1` is strengthened and `game/tests/test_garage_persistent_pictures.gd` supplies separate-process native persistence checks. Existing Garage tests and concurrent car/handling/UI work are not edited by this pass.

The first new appearance still needs one native capture. Pictures update when paint, parts, visible condition or conservative visual dependencies change. The cache format changes once for this implementation; old keys cannot safely be reassigned without their original appearance/source metadata. This improves stored-picture reuse, not the cold construction/shader cost of the main interactive Garage.
