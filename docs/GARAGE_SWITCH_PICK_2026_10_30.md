# Garage switch: defer wash picking geometry

Car replacement used to generate triangle meshes for wash hit-testing synchronously, even when the player was only browsing. The initial Garage already postpones this work until `pick_body_surface`; replacement and kit changes now follow the same rule. Every change still clears the old list. Non-Garage showroom behavior is unchanged. The original working-tree version is saved at `build/garage-switch-perf/car_showroom-before.gd`; it includes pre-existing work and is not the Git baseline.

## Measurements and checks

- Isolated headless single-run comparison of `test_garage_switch_pick.gd` with six actual cars: callback times (ms) before/after were Compact 200.730/177.382, Pickup 36.408/33.132, Kart 264.678/254.743, Forklift 290.517/248.277, Electric 256.003/242.398, Hovercraft 220.571/176.831. These are exploratory single samples, not a device or frame-time benchmark. After the change the first pick took 1.7–71.4 ms, so wash entry can still encounter that cost. The live model and reveal are still built synchronously.
- Native Compatibility on the RTX 3090: focused switch/pick test 22 checks, zero failures. It checks each real current car, stale-pick invalidation after a kit change, a projected body hit and `wash_at`. First-pick measurements were 2.1–73.1 ms.
- After adding a no-wait Pickup-to-Kart interruption to that test, headless passed 25 checks, including the final live model, settled pedestal and first pick's ownership. The three additional checks have not been run graphically.
- Native Compatibility `test_garage_wash_animation.gd`: original staged source and changed source both produced 146 checks and the same four failures: exact serialized wash on restart, and forklift picking/contact/cleaning. These are retained findings, not passes. Headless `test_car_wash.gd` likewise reported the same 1655 checks and one failure in both versions ("five independent cars; no PB writes"). Headless changed wash-animation additionally reports "droplets move during hold"; it was not compared in headless mode.
- Native `test_garage_car_transition.gd` could not reach its assertions: its setup calls Garage without waiting for ready pictures, so it dereferenced a null page and was interrupted. The focused test covers successive replacements but does not replace that visual transition test.
- `profile_garage_pedestal.gd` measured 20 repeated headless pedestal constructions at 3.149 ms median and 4.082 ms maximum. No pedestal caching change was made.

All commands used `python scripts/run_no_crash_dialog.py --` with the pinned `C:\apps\Godot 4.7.2\Godot_v4.7.2-stable_win64_console.exe`, `--audio-driver Dummy`, isolated APPDATA/LOCALAPPDATA under `build/garage-switch-perf`, and empty `BMT_API_URL`. Headless checks passed `--headless --path game`; native checks passed `--path game --rendering-method gl_compatibility --position 10000,10000`. Each used `--script res://tests/<name>.gd`. The original control used `--path build/garage-switch-perf/baseline/game`, a staged project whose `ui/car_showroom.gd` is the saved original and whose other project content refers to the same working tree. Each animation run wrote to its own evidence directory under `build/garage-switch-perf`. The sandbox emitted the same Windows root certificate-store error; no network operation was required.
