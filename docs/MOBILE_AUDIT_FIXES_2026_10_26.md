## Support and symbols

Settings > Help > **Copy diagnostic report** is an explicit local clipboard action available to guests and opted-out players. It contains build/source identity, engine/platform/renderer, bounded device/OS descriptions and up to four recent Android crash/ANR records. The final report is at most 16 KiB. Android traces are read only on that action, at most 256 KiB per trace, with at most 24 validated first-party frames per exit. Native protobuf parsing selects the crashing thread when its ID is available. Raw logs, abort messages, memory/register dumps, process IDs, paths, account fields, credentials, tracks and recordings are discarded. Missing, rotated, malformed or unavailable OS traces produce an otherwise useful report without frames.

Backend logs add `bmt_backend.module:function:line` (or `external`) beside the existing request ID and exception type. They do not add exception text, locals or submitted bodies. The quality dashboard explicitly distinguishes this local support route from its existing signed-in, consented telemetry; it continues to report automatic guest/crash-stack/Play-vitals ingestion as unavailable.

`build_track_geometry.ps1` now compiles debug information, extracts separate debug files, strips the packaged library and writes `build/symbols/<packaged-binary-sha256>/mapping.json`. Keep that directory privately with each release's build identity, source checkpoint, APK/AAB hash, native ELF build IDs and any Java obfuscation mapping. The disposable Windows symbol fixture proves actual address-to-source resolution; production libraries were not rebuilt in this task. Obtain the **matching** official Godot Android template symbols, or symbols from the identical custom template build, following [Godot's symbol guidance](https://docs.godotengine.org/en/stable/tutorials/platform/android/resolving_crashes_on_android.html).

For a player report, identify its build and matching release artifact first, resolve retained relative PCs against the matching library/symbols, and correlate backend request IDs with safe failure sites. Review Play Console Android vitals after each rollout and regularly thereafter; group crashes/ANRs by build, OS/device, frequency and affected users, resolve native symbols, and track each reproduced regression to a verification build. Record the review window and provider outage explicitly. This is an operator workflow, not a newly connected feed. Android's [exit-info reference](https://developer.android.com/reference/android/app/ApplicationExitInfo#getTraceInputStream()) documents nullable/rotated traces and native protobuf tombstones from API 31; the [AOSP schema](https://android.googlesource.com/platform/system/core/+/refs/heads/main/debuggerd/proto/tombstone.proto) defines the fields read by the bounded parser.
