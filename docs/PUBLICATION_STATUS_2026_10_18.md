# Clear publication outcomes — 2026-10-18

PUB01 makes publication status explicit. PUB02 treats a confirmed public receipt as published even while local caching finishes. PUB03 keeps an open outcome current without another Publish action. G01/R01/Q01 retain existing racing, durable publication processing and native verification.

The old app appended “Your publication request is saved and will retry” to every result whose local state was not `published`. This included ordinary server `queued`/`verifying` responses and `finishing`, where the server had already published the track. The generic dialog then labelled all of these “Publication queued”. This message was not evidence that a transport retry had actually occurred.

The Publish callback now opens a dialog driven by the exact saved publication job. Queued and checking states say **Not published yet**, with the current check stage and permission to close the message. A public receipt in `finishing` or `published` says **Track published** and that other players can access it; unfinished local downloading is stated separately. Actual rejection says **Track not published** and preserves its actionable cause. An upload without a confirming reply says **Publication not confirmed**, preserving the possibility that the server accepted it. Automatic continuation advice requires the game to stay open, signed in and online.

The same dialog follows the existing lifecycle signal through checking, publication, local finalization or failure. It does not resubmit Publish, add polling, navigate on background completion or reopen after dismissal. Changing account scope dismisses the previous owner's notice. The original styled scenery, controls, touch targets, focus, input isolation and generic notices remain.

Changed runtime files are `game/core/app.gd` (the publication callback only) and `game/ui/fault_dialog.gd`. `game/tests/test_publication_notice.gd` and its generated UID cover state classification, the actual app callback, live transitions, publication before local finalization, missing confirmation, actionable rejection, dismissal, account fencing and navigation. The existing local-publication regression separately exercises real journals, exact trajectory data, immutable retries and consent.
