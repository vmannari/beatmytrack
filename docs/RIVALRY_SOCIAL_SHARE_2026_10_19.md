# Rivalry card sharing to social apps — 2026-10-19

The owner requests direct sharing to WhatsApp and other social apps, and explicitly selects the designed results-card image with accompanying text. RSS01-RSS03 replaces Rivalry's Android text-only handoff with a rendered PNG plus the exact `finale_share_text()` caption through the system chooser. One Share results tap prepares the image and opens sharing. The preview offers Share again; the recipient and final Send action remain in the selected app. This implementation targets the game's Android platform. The Windows preview keeps copied text and adds Save image; a Windows native sharing chooser is not implemented.

RSS01 renders the existing refined card independently at 1600×860, with actual pinned results, country/name, car and local cosmetics. The surrounding game, close button, copied status and action controls are absent from the image. The capture uses an isolated bounded viewport, warms the existing static car render, then frees its temporary window/viewport. It cancels if the owning preview disappears. The prepared PNG is cached only in that preview and capped at 4 MiB. No public results URL, new image-generation service or backend data is created.

RSS02 extends the original Android adapter with `shareResults(requestId, png, text)`. The intent contains `image/png`, the stream URI and exact text, with matching ClipData and read grants. A private, non-exported, read-only `RivalryShareProvider` exposes only generated PNG files in the app's cache. Package-specific `${applicationId}` authority wiring works with the configured application ID. Unique staged writes and a six-image/24-hour cleanup policy give a 24 MiB retained-image budget; one new receipt can temporarily coexist during a save. Unknown names, traversal, foreign authorities and write access are refused. No new SDK, dependency, storage permission or external account connection is added. Existing challenge/track text sharing is retained.

RSS03 coalesces repeated taps during image preparation and rechecks account/car scope, snapshot ownership, week/group, results text and navigation before native dispatch. Closing or navigating cancels late image completion. Native launch errors carry the request identity and allow retry; older errors cannot replace a newer request. The UI says Ready to share, and never treats opening/cancelling a chooser as confirmed delivery. On desktop, the Save image action uses the native save dialog, rechecks the same context and writes the generated PNG; the user chooses the file path.
