## Geometry and contract

`SplineRoad` uses deterministic centripetal Catmull–Rom tangents and cubic Hermite evaluation across four spans. Endpoints use one-sided tangents. Every span includes its exact authored endpoint, so all five interpolation points remain represented in the sampled geometry. Width interpolates linearly by distance along each sampled span, without width overshoot. Adjacent control points must be at least 2 m apart; finite world samples must remain inside the existing ±120 m map bounds. Existing piece/road-length budgets remain active.

The additive `creator-track-v5` spline variant stores `spline_points` (five local coordinate pairs) and `point_widths` (five widths). The first local point is `[0,0]`; moving it rebases the local frame and keeps the other four world points fixed. The existing position/heading/flip fields control the whole block. `width` is the maximum point width for conservative bounds. Endpoint poses use the actual fitted tangent, and connected mouth matching uses actual endpoint widths rather than that maximum. Join width blending ends before the next internal interpolation point, preserving all three internal widths. Other block geometry retains its existing behavior.

`RoadPieces.section_geometry` supplies the same spline/width samples to rendering, outlines/kerbs, rasterized drivable surfaces, roadside runs and automatic routing. Start-line placement uses the local interpolated width. No manual waypoints are added. Tight user-shaped roads can still produce folded offset edges, as with existing sharp curves; this block does not introduce a road clearance or minimum bend-radius rule.

Compiler version advances from **creator-compiler-20 to creator-compiler-21**, and both game and canonical verifier use the new helper. The standalone verifier staging allowlist includes it. The authoring schema JSON adds bounded spline fields and variant conditions; existing v5 documents still load without migration or deletion. Compiler/hash golden identities change; original geometry, recorded input frames, physics/rules versions, times and lap assertions remain intact. In particular the existing verified oval fixture changes only `expected_manifest.compiler_version` and `expected_manifest.track_content_hash`; its stored recording and 12,757-tick race remain unchanged.
