The moderation scope here changes track visibility and new-ticket availability through the existing hidden-track contract. It does not delete content, remove submitted evidence, rewrite accepted results or transfer balances. Restoration refuses a different owning case or intervening visibility moderation; ambiguous same-second moderation is conservatively refused. Cases use shared owner/analyst credential roles, not individual staff attribution.

Competition reads use one consistent transaction, at most 200 members/5 slots/1,000 bests and the first 500 linked attempts in deterministic order. They never fetch proof/ghost objects or invoke the verifier. Creator source runs deliberately seeded into challenges remain valid without a challenge-ticket binding. A corrupt linked source remains visible rather than silently becoming an accepted rank. Archived timing alone cannot prove original acceptance. Current points are explained using the existing rivalry policy; reads never change official scores.

Network and compute:

- Reuse the existing authenticated, account/origin-separated durable telemetry outbox: 50 events / 64 KiB per packet, 1,000 events / 2 MiB local queue, stable-ID retries and acknowledgement after commit. A backend feature flag plus negotiated `quality_schema_version=1` is required. `BMT_CLIENT_QUALITY_ENABLED` defaults false and requires telemetry enabled.
- Frames become eight integer buckets every five minutes, separated by menu/race/editor scene. No per-frame requests or stored frame arrays. Spatial sampling reads presentation state once a second, using 20 m cells / 32 route segments and retaining the 16 lowest stable cell hashes per ten-minute window. It is censored sampled presence, not total dwell time, distinct drivers or validated race evidence. Inclusion probabilities are unavailable; local dropped-cell counts are not currently projected to Studio.
- Quality events are passive for the existing five-minute idle flush rule. They do not trigger one-minute journey flushes; actual product activity retains its original cadence. No transport or persistence worker starts during an ordinary foreground race; pooled identifiers reserve 32 entries for product/race observations. Extended races may lose optional counters when the pool/outbox budget is exhausted.
- The Windows collector fixture measured **1.0034 µs/frame** and **18.472 µs/cell observation**. Its 19-event compact packet was **5,852 bytes**. A single-scene hour has at most 12 frame summaries and 96 retained-cell summaries, plus at most four startup exit observations. Packet size and collector timing are measured; hourly body traffic, TLS/radio cost and physical-device CPU remain unmeasured. Retries, existing product traffic and compressed transport affect actual traffic.
- The existing lower-priority product worker performs grouped counter upserts in the same bounded projection transaction. No new worker instance, simulation, geometry scan or object download is introduced. Diagnostic facts use 64-bit counters and paced retention under the existing fact retention setting. Studio reads prepared counters with a 1,000-row response ceiling; it does not scan raw events. New indexed ordering supports recent creator/rivalry/challenge lists. Two small API reads serve each new workspace: context (no operational count queries) and its bounded data query. Large-population query load has not been benchmarked for this slice.
- Android reads at most four OS exit records, once outside racing, with a persisted cursor. It uploads the reason and collection time; the original exit timestamp stays in the local cursor. It never reads trace streams, PIDs, device IDs, raw logs or credentials. These describe the previous process and cannot prove a crash affected the current signed-in account. API availability is documented by [Android ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo).

Provider contracts follow [Google Play ProductPurchaseV2](https://developers.google.com/android-publisher/api-ref/rest/v3/purchases.productsv2) and [AdMob SSV](https://developers.google.com/admob/android/ssv). The Play adapter checks explicit package, exact product, server account binding, quantity, state, completion time and refundable quantity; pending/test/refund state stays explicit. AdMob matches [Google's reference verifier](https://github.com/tink-crypto/tink-java-apps/blob/main/rewardedads/src/main/java/com/google/crypto/tink/apps/rewardedads/RewardedAdsVerifier.java): percent-decode the URI query once, preserve literal plus signs and parameter order, then authenticate before parsing business fields. It rejects duplicate/unknown parameters and unsupported rewards, and caches trusted Google EC keys for one hour with paced refresh. Signature validation alone never grants resumes: configured placement, server-issued intent, expiry, permanent transaction dedupe and atomic fulfillment are still required. No production provider call, purchase, ad grant or payout was performed.
