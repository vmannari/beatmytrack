# Local drafts and explicit verified publication — 2026-10-12

Owner requirement `STUDIO-LOCAL-DRAFTS-01`, related Studio BMT-030/BMT-032 and verification B01/R01: the server catalogue contains published tracks. Saving, editing, deleting, local creator testing and idle recovery do not upload drafts or fetch remote draft masters. The root Studio revision report covers the other workspaces and telemetry changes.

Drafts and the completed creator trajectory stay in the existing account/device-scoped local library. `prepare_test` compiles and validates locally; a completed, eligible ordered creator lap saves its exact final tick count and sampled trajectory. It does not save another full control replay. Root App integration passes the actual witness recording with an empty control array, retaining document/car/account snapshots and the durable-save retry dialog. Untimed Practice remains independent; an incomplete/ineligible witness cannot unlock Publish.

Explicit Publish negotiates `publication_workflow_version=2` and uploads one immutable document plus its saved creator trajectory to `POST /v1/publications`. The durable publication intent is a processing job, separate from `tracks`/`track_versions`; no track row, version, creator run or publishing-slot debit exists until verification succeeds. Each intent has a permanent owner/operation-key/content identity and the existing shared bounded queue admission (eight pending jobs per player/global configured capacity). A leased worker validates track geometry/build/config and checks the same timestamped trajectory used for ordinary races. It checks **one creator validity lap** under the existing `creator_test` contract; the resulting published ordinary-race manifest retains **five laps**. Ghosts and control/physics replay are not acceptance requirements.

Publication finalization atomically creates/adopts the stable owner/authoring track ID, immutable version, verified creator run and its pinned creator board/ticket, publication events and slot consumption. A duplicate operation or identical already-published content returns the committed receipt without another run or slot debit. Invalid evidence/build mismatch does not create a catalogue entry. Insufficient capacity rolls back every content/proof/slot write, retains the local draft and the explicit publication intent, and offers Retry after capacity is available. Foreground real race jobs take priority, then publication, then artificial/background work. A stale lease token cannot finalize. The first explicit Publish timestamps a fresh operation key after local storage; recorded/uncertain attempts retain their original key. An already-known owner/body-bound permanent intent remains readable after that key's new-operation admission window expires, while expired unknown keys cannot create effects.

The client uses the initial POST response as status instead of immediately reading it again; pending status reads obey the server poll cadence. Lost responses reuse the exact saved package/key. New control capture is not reconstructed or re-driven. Successful handoff retains the current cache/binding/favourites behavior and preserves newer/unreadable local edits. A fresh account without a last-track preference remains valid; migration no longer inserts an invalid empty preference.

Migration 0028 parks previously queued/validating remote authoring jobs as `legacy_saved`, clears/fences their leases and releases their existing shared queue counters. `legacy_workflow_snapshot` preserves the entire original status/failure/detail/attempt/lease metadata, including a maximum-length existing diagnostic. Source versions, IDs, content and published rows remain intact. The default worker does not process these retired authoring jobs, so they cannot consume compute or permanently occupy a player's eight-job quota.

Deprecated draft APIs and the old publish endpoint return `410 LOCAL_DRAFTS_ONLY` before storage/mutation. `Settings.local_drafts_only` defaults true; false is accepted only for explicitly identified `environment=test` compatibility fixtures. It cannot silently enable remote drafts in development or production. `GET /me/tracks`, including heads, returns published versions only. Historical server rows/objects are preserved; the owner has not authorized deleting them. Old local autosync journals/archive receipts are preserved without upload, remote-head restoration or background archive calls. Old race-outbox publication metadata is retained without implicitly publishing; accepted recorded races still complete normally.

Product ingress under the same default rejects retired `editor_opened`/`draft_saved` observations. Track exposures/selections and referenced race observations use one indexed batch lookup of published version IDs; private, unknown and missing exposure references retain only a redacted rejection record. Generic race journey events without a published reference keep no local car/biome/ticket/mode context. New outboxes have no publication target or publication key; old recorded metadata is preserved. Product reports explicitly mark `local_draft_metrics.available=false` and keep the creator funnel as historical data with its original definition. The current publication-request journey is separately ordered and waits the full seven-day follow-up/cohort day and projector watermark; historical draft facts are not deleted or reinterpreted.

The three journey frontiers share a hard 128-milestone profile bound. Every currently proved ordered step (including all completed conversions, partial steps and their earliest anchors) is retained before alternate candidates are allocated in deterministic order. If the global budget omits a prefix's candidates, that prefix is marked uncertain rather than restating a proved mature conversion as absent. Proved steps are unioned before the bound for all profile sizes, including a partial valid request beyond the first 18 earlier candidates in a profile smaller than 128.

Pending and failed publication objects are included in both reference-aware GC discovery and final pinned-lock rechecks, with indexed hashes. Publication intent/evidence retention is currently permanent, matching permanent effect deduplication; this is not an expiring enhanced diagnostic capture implementation. There is no draft reinstall recovery from the server. Published content remains downloadable. Owner/analyst publication processing list/detail reads are bounded, use a consistent count/list snapshot, disclose source hashes/contracts and accepted creator-run linkage, and never load private documents or trajectory objects. Pending count is exact under shared admission; failure probing caps at 5,000 with an explicit capped flag.
