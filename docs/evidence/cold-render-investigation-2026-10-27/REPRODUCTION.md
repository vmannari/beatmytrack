# Evidence and reproduction

The main implementation plan is [COLD_RENDER_IMPROVEMENT_PLAN_2026_10_27.md](../../COLD_RENDER_IMPROVEMENT_PLAN_2026_10_27.md). `report.json` records commands, source/engine hashes, individual exits, case metrics and the remaining gates. `checksums.json` covers the archived evidence files other than itself. Pair assertion counts with process exits: the initial App/capture failures and the Mobile teardown timeout remain evidence.

`cases/` contains all eleven complete Garage result reports and their native studio images. `native/` contains owned-child stack samples. `race/` contains the twelve-load actual-App profile and its bounded UTC frame list. `source-start/` contains the twelve relevant baseline scripts. Only seven Garage scripts were actually reloaded from the frozen set; this is not a whole-project source snapshot. `runs/` retains raw outputs and execution receipts, including failed attempts.

To repeat these diagnostic harnesses, restore `harness/` files to `build/cold-render-investigation-2026-10-27/` in a matching project tree and restore `source-start/` as that directory's `frozen-original/`. The Python runners expect the repository as the working directory. Use the exact engine hash in `report.json`; the native function-pointer diagnostic refuses another executable. Build with the recorded MinGW compiler. Compile `link_bench-v2.cpp` for the corrected call-order/shared-context controls and `link_bench.cpp` for the process-isolation/binary controls. The compiler commands in the report are reproduction commands; apply the appropriate versioned source filename.

Fresh `run_probe.py` labels make private application profiles, clear inherited BMT overrides, and write an explicit offline backend configuration. Same-cache repeats are explicit `--reuse-profile` cases. The original first App ownership assertion was corrected in the final harness; its historical failure is retained in its original report/log. Source changes elsewhere in the shared project can affect a new run. Global driver caches are not reset, and these scripts do not establish target-device behavior.

`generated-glsl/` holds the actual captured stages for the native harness, with engine attribution. Program binaries, native executables/DLLs, full application profiles and the approximately 30.8 MB engine cache are not copied into this evidence set. Their hashes or aggregate sizes are recorded. The recorded program-binary results only validate linking in a fresh context; drawing a real Garage with an imported program remains a required next experiment.

The initial API-inspection attempt's sandbox log-rotation failure is retained. Reproduction should use isolated application profiles, as the corrected runner does. The local PowerShell image comparison uses process-local `-ExecutionPolicy Bypass`; it does not change machine policy. No owner process, user save, attached device, backend deployment or root Git index is needed for the desktop diagnostics.
