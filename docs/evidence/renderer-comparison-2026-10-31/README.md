# Desktop renderer observations — 31 October 2026

These are **uncontrolled exploratory Windows desktop observations**, not the requested Android A/B, release-build certification or proof that either renderer is faster. They use private offline records and a fresh application profile per renderer, but driver caches were not cleared. Other processes were active. The aggregate set of `game` source files changed during both runs (Compatibility: 1,903 → 1,904; Mobile: 1,905 → 1,906), and the original runner stored aggregate hashes only, not a file-by-file start manifest. The precise changed paths and whether they affected the running scene therefore cannot be reconstructed from these records. The runner has since been improved to save per-file start/end manifests including relevant assets; this improvement was not present in the observations below.

Subsequent filesystem timestamp triage found `game/core/app.gd` and `game/ui/track_of_day_page.gd` last written at 11:48:50 and 11:48:49, respectively, between the end of the Compatibility process log (11:48:35) and the start of the Mobile process log (11:49:07), local time. Several test scripts also had writes during or around the observation interval. These timestamps show intervening edits to production source, but do not recover the earlier bytes or prove which changes influenced either result. They reinforce that the two captures and timings are not a controlled comparison.

Both runs used pinned Godot 4.7.2, an RTX 3090, 1280×720, desktop scale 1.0, viewport MSAA setting 1 (2×), display-reported 120 Hz and `Engine.max_fps=0`. Both are debug-build observations. The probe logs the actual renderer: `gl_compatibility` with OpenGL 3.3 and `mobile` with Vulkan 1.4.351. Each starts the real App, loads the same unscored Star fixture with an isolated default Compact and overhead camera, takes an image at ready/tick zero, then repeats the race in that process. Both had 8 checks and zero assertion failures, process exit zero, and an offline Windows root-certificate-store error.

Each callback interval is sampled between Godot `process_frame` callbacks; it is **not an actual presentation gap, GPU duration or input acknowledgment**. The p50/p95/p99, counts, snapshot draw counts and breakdowns are in each renderer's `report.json`. The observed Mobile differences do not establish a causal gain because the programs, source state, background load and driver cache histories were not controlled. The large Mobile first interval still shows a substantial observed pause in this one desktop process. Startup and race timing have different boundaries; energy, PSS, device thermal state and first driven particle effects were not measured.

The paired screenshots are [Compatibility first](gl_compatibility/star-0.png), [Compatibility repeat](gl_compatibility/star-1.png), [Mobile first](mobile/star-0.png) and [Mobile repeat](mobile/star-1.png). Visual inspection finds a broad warm haze in the upper left of both Mobile frames and more pronounced dark, soft HUD backings; neither is equally visible in the Compatibility frames. This is an observed image discrepancy, **not a diagnosis** or an Android acceptance result. The scenes use the same intended fixture, view, tick and frame size, but the source snapshot caveat above applies.

The [comparison](capture-differences.json) shows Compatibility first/repeat RGB are identical; the two Mobile screenshots differ in 1,966 of 921,600 pixels, of which 12 differ by more than 2 in any RGB channel. Cross-renderer first captures differ in 890,614 pixels; 830,658 exceed 2/255 in a channel and mean absolute RGB difference is 13.461/255. The upper-left 320×180 area has mean difference 18.655/255. Final PNG alpha values are 255 throughout; this says nothing conclusive about intermediate material or viewport alpha.

Read-only triage: the Pine scene enables a full-screen warm sun/cloud effect (`game/core/game.gd:_update_cloud_shadows`, `game/track/cloud_shadow.gdshader`). Its depth reconstruction has separate Compatibility/Vulkan clip-space branches (`game/track/shadow_depth.gdshaderinc`). The HUD uses 20 translucent polygons to draw soft backings (`game/ui/hud_frame.gd:_soft_backing`). These are candidates for a controlled one-factor ablation, not proven causes. The Adreno Compatibility-only `mobile_world_aa` path is not selected on either desktop process. Principal biome albedo, livery sticker and dust colour samplers have `source_color` hints; data/mask/depth/normal samplers must not be changed merely for lacking that hint.

Exact original commands, exits, aggregate hashes and logs: `gl_compatibility/execution.json`, `gl_compatibility/process.log`, `mobile/execution.json`, `mobile/process.log`. `desktop_probe.gd` and `compare_captures.gd` are the owned probes; `run_desktop.py` launches the pinned engine through the required crash-dialog wrapper and applies an owned-process 240-second timeout. For a repeat, run `python docs/evidence/renderer-comparison-2026-10-31/run_desktop.py gl_compatibility <fresh-label>` and similarly `mobile <fresh-label>` from the repository root; output and isolated profiles go under `build/renderer-comparison-2026-10-31/`. # Car construction checkpoint investigation

The frozen Compatibility and Mobile source trees have the same `game/vehicle/car_visual.gd` SHA-256 `605d082561b0d435521167412336cefaF526d108fae6470ac62ad98002f72362`. Their checkpoint budget is 4,000 microseconds of elapsed time; on reaching it the coroutine yields until the next `process_frame`. Checkpoints occur in the Compact detail, sibling batching and transform-frame batching loops, but some operations, including the rest-pose snapshot, are indivisible. The budget therefore does not enforce a maximum frame duration. The Game waits for `model_ready` while continuing its own preparation checkpoints.

The GL first Star case reported 397 car yields and 7.971 seconds in car preparation, with a 56.191 ms maximum measured slice at snapshot. The Mobile **later** Star attempt after the first timeout reported 1,153 yields and 23.118 seconds, with a 67.070 ms maximum measured slice at snapshot. Their apparent approximately 20 ms per yield is compatible with the reported 50 Hz cadence, but these are elapsed times, not isolated CPU or idle time, and the cases do not have established matching cold state. These figures do not establish why the counts differ.

An existing frozen-source six-car parity test, `res://tests/test_cooperative_car_model.gd`, passed 18/18 using Godot 4.7.2 headless, isolated `APPDATA`, and `scripts/run_no_crash_dialog.py`; the process returned 0 and printed the Windows root-certificate-store warning. This test compares cooperative and synchronous geometry/materials, not displayed frames, GPU work, cancellation responsiveness or Android performance.

`car_budget_probe.gd` is a separate offline diagnostic. It uses that same frozen project with a 50 FPS cap and interleaves 4, 8, 8, 4 ms budgets for a cooperative Compact, clears several in-process caches, records `process_frame` callback intervals and checkpoint maxima, and compares complete geometry/material signatures. Execute with the scoped wrapper and an isolated `APPDATA`:

```powershell
python scripts/run_no_crash_dialog.py -- 'C:/apps/Godot 4.7.2/Godot_v4.7.2-stable_win64_console.exe' --headless --path 'build/android-renderer-comparison-20261031/snapshot/game' --script '<absolute path to car_budget_probe.gd>'
```

The run exited 0; raw output is `build/android-renderer-comparison-20261031/car-budget-headless.log` (PowerShell formats the certificate warning). The four runs took 2.617, 0.539, 0.583 and 1.042 s with 132, 28, 30 and 53 yields. Callback maxima were 25.781, 20.525, 23.299 and 22.528 ms; slice maxima were 25.637, 20.433, 23.214 and 22.383 ms, all at snapshot. Geometry/material signatures matched. The first and last 4 ms runs differ substantially despite explicitly clearing selected caches, showing warm-up/order confounding. This single headless desktop experiment has no rendered frame, real input, GPU workload or device measurements. It does not demonstrate that changing the phone's budget is safe; no budget or antialiasing changes were made.
