# Biome shader preparation

This is a source module and a checked patch for the pinned Godot 4.7.2 engine. It is not a GDExtension or a GL function-pointer hook. Installed engines and export templates are never replaced by these scripts.

`fetch_engine.py` downloads the official tag into `build/biome-shader-profiles-20261106`. `prepare_engine.py` retains originals, checks patch anchors, installs this module and writes the source patch and fingerprint. `build_engine.py` builds an isolated Windows Compatibility-capable debug template. The template enables Godot's supported path override option for isolated tests. It does not produce an Android APK or an Android export template.

`build_android.py` adds Android native-library build commands and a read-only preflight for that prepared engine. Run `python native/biome_shader_profiles/build_android.py --arch arm64 --target template_debug` to verify the pinned source/module fingerprint and required NDK before any build. The pinned engine requires NDK `29.0.14206865`; an older NDK is rejected. The tool does not download the NDK automatically. `--build` runs SCons only when preflight passes, retaining both OpenGL and Vulkan support. `--target template_release` selects the release library and `--arch x86_64` selects an emulator library. `--receipt <path>` retains the command, preflight result and any built-library hashes.

Preflight also requires the engine-pinned Swappy `from-source-2025-01-31` libraries and checks all four archive hashes; `swappy=yes` prevents silent loss of frame pacing. `profiler=none` explicitly selects the default external-profiler setting. The optional Perfetto installer chooses an unpinned latest version and is not run. The validated SDK is passed through both SCons arguments and the child environment because platform discovery happens before argument parsing. `GIT_OPTIONAL_LOCKS=0` is also limited to the child environment. New receipts must remain under this repository's build/evidence directories; existing receipts are never overwritten. Separate module/platform build-input hashes, including `config.py` and `SCsub`, are checked before and after compilation without changing the qualified runtime/profile fingerprint.

The Android command sets `generate_android_binaries=no`: it builds native libraries in the isolated engine tree without creating a game APK/AAB, installing export templates, signing or contacting a device. Turning those libraries into matching custom Android templates is a separate packaging step. The ordinary `scripts/dev.ps1` Android export continues to verify the official template; this tool does not silently substitute a custom engine.

The task-owned [ARM64 debug packaging helper](../../docs/evidence/loading-half-2026-11-06/engine/package_android_debug.py) overlays a successful matching native build onto the pinned official Android source ZIP. Default preflight verifies receipt, source/build/dependency identity and ELF headers while skipping the large official archive/native output hashes; `--package --build-receipt <successful-build.json>` performs those checks plus the NDK runtime comparison, then writes a new debug AAR/source ZIP beneath `build/loading-half-20261106`. Every retained Java/resource/source entry remains byte-exact, every output entry receives a CRC/hash check, and only the two ARM64 JNI libraries remain. The output deliberately omits the official release AAR. This reuses official Java bytecode for the native-only patch; it does not rebuild Java or establish Android runtime compatibility. [Packaging commands and remaining dependencies](../../docs/evidence/loading-half-2026-11-06/engine/PACKAGING.md) describe the isolated follow-up path. [The completed native build/package report](../../docs/evidence/loading-half-2026-11-06/engine/REPORT.md) records identities and limits. Installed templates and the ordinary export hash check remain untouched.

Android selective preparation remains **unqualified**. Existing manifest contexts were captured on desktop NVIDIA hardware and cannot stand in for phone/tablet contexts. Building a library is not a performance result. Use a matching custom-engine Android client to capture and review exact device/driver/car/biome/settings coverage, fallback controls, visuals, frame timing and lifecycle behavior before promoting Android profiles. Until such matching profiles exist, the engine retains ordinary preparation.

The game discovers the `BMTShaderProfiles` engine singleton. Engines without it, other renderers, missing/mismatched profiles and unknown shader sources retain normal preparation. The profile selects exact specialization masks for a known expanded shader source. A requested specialization absent from preparation still uses the engine's synchronous compile-on-bind path; nothing substitutes a simpler shader or skips rendering.

Profiles are grouped by biome, car, graphics settings and exact renderer/driver/engine context. `game/rendering/biome_shader_profiles.json` contains reviewed first-draw coverage, not GPU binaries. Engine patch/module fingerprints invalidate earlier contexts; expanded source hashes invalidate changed shader sources. Existing persistent binary caches remain supported and may import additional programs; profile selection does not delete cached programs.

The engine observes all four GLES3 draw APIs, excludes empty draws, and keeps bounded first-use records. A bind or uniform setup alone does not establish coverage. Program IDs are only transient registry keys; exported identities use shader source, variant and specialization. Reused IDs and freed versions are handled. Missing variants report both first-draw phase and compilation phase/cost; these can differ. The ordinary on-demand path remains responsible for correctness. Pause closes the race observation scope before pause-menu draws; resume uses actual applied race settings.

Use `game/tests/profile_biome_shader_profiles.gd` on the isolated engine to collect readiness, effects and opening-lap coverage. Pass `--first-emission --biomes-only` for the five-biome Compact sequence. The `--inject-shader-miss` positive-control run must not become a production manifest. `collect_profiles.py --output <reviewed-manifest> <profiles.json> ...` combines measured entries by exact context. Review, repeat with the profile enabled, compare views and verify late compilations before copying the manifest into the game. Telemetry is evidence for a profile update, never automatic permission to promote an untested profile.

Production telemetry uses the existing opt-in, authenticated queue and capability negotiation. Bounded summaries include up to 16 missing variants, prioritized by late compilation, while retaining total counts and dropped-record counts. Full local test captures retain the expanded inventory. Raw GLSL, driver strings and player identifiers are excluded from the event properties. Existing account erasure/retention apply. The admin report at `/v1/admin/shader-profiles` reads a bounded indexed receipt window and labels its incomplete population coverage. Backend migration 0074 adds only that partial index; no rollout is performed by these scripts.
